## 1. TF 사슬 — 누가 어느 구간을 내는가

```
map ──[cartographer]──► odom ──[EKF]──► base_link ──[robot_state_publisher]──► lidar_v1_1
```

| 구간 | 발행자 | 근거 |
|---|---|---|
| `map` → `odom` | cartographer | `my_cartographer.lua` `published_frame = "odom"` |
| `odom` → `base_link` | **EKF** | `ekf.yaml` `publish_tf: true` |
| `base_link` → `lidar_v1_1` | robot_state_publisher | URDF `Rigid 40` (fixed joint) |

**세 발행자가 각자 한 구간씩 맡는다. 하나라도 빠지면 사슬이 끊겨 SLAM 이 안 돈다.**
→ 이것이 11-01 에 **EKF 를 못 뺀 이유**다 (`DEBUG_LOG_2026-11-01.md` 3절). 센서가 바퀴 하나뿐이라 융합은 없는데도
`odom→base_link` 를 내는 노드가 EKF 뿐이다.

URDF 에 좌표도 실제로 들어 있다 (0 으로 비어 있지 않다):

```xml
<joint name="Rigid 40" type="fixed">
  <origin xyz="-0.046963 0.002846 0.1223" rpy="0 0 0"/>
  <parent link="base_link"/>  <child link="lidar_v1_1"/>
</joint>
```
→ 라이다가 `base_link` 보다 **12.2cm 위, 4.7cm 뒤**. CAD 에서 뽑은 값으로 보인다.
`frame_id` 이름도 launch(`lidar_v1_1`) ↔ URDF 링크명이 일치한다.

## 2. 라이다 단독(STAGE 3)에는 TF 가 필요 없다

`sllidar_node` 는 `/scan` 을 **발행만** 한다. TF 를 조회하지도 발행하지도 않고,
헤더에 `frame_id: lidar_v1_1` 이라는 **이름만** 박는다. 그래서 이건 TF 없이 된다:

```bash
ros2 topic hz /scan
ros2 topic echo /scan --field ranges
```

**단 RViz 로 보려면 TF 가 필요하다.** RViz 는 `lidar_v1_1` 을 Fixed Frame 으로 변환해야
점을 찍는다. 없으면 `No transform` 에러만 뜨고 아무것도 안 보인다.
→ **우회: RViz 의 Fixed Frame 을 `lidar_v1_1` 로 직접 설정한다.** 변환할 게 없어진다.
STAGE 3(라이다 단독 검증)에서는 이게 정석이다.

## 3. URDF 바퀴 간격이 실측과 다른 것 — SLAM 에는 영향 없다

URDF 는 바퀴를 `y=±0.0825`(간격 **0.165m**)로 적어놨으나 실측은 **0.22m** 다.
09-03 로그 3절이 "CAD 기준값이라 보류 중" 으로 남겨둔 항목이다.

**실기 SLAM 과 무관하다.** 오도메트리는 URDF 를 읽지 않고 `motor_drive_1.py` 의
`wheel_base=0.22` 파라미터를 쓴다. URDF 의 바퀴 좌표가 쓰이는 곳은
**RViz 의 바퀴 그림 위치**와 **Gazebo 시뮬레이션**뿐이다.
→ 실기에서는 "RViz 바퀴가 좀 좁아 보인다" 외에 아무 영향이 없다. **보류해둔 판단이 맞다.**
(Jazzy 에서는 Gazebo Classic 을 못 쓰므로 시뮬 영향도 현재는 없다)

## 4. ★ 새 미해결 — 라이다 장착 방향(`rpy`)이 미검증이다

`Rigid 40` 의 `rpy="0 0 0"` 은 **라이다의 0° 방향이 로봇 전진(+x)과 정확히 일치한다**는 뜻이다.
케이블이 뒤로 가게 돌려 꽂았다든가 해서 실제로 180° 돌아가 있으면
**지도가 통째로 회전해서 생긴다.** 위치 오차가 아니라 **방향 오차**라
값만 봐서는 눈치채기 어렵다 — `DEBUG_LOG_2026-11-01.md` 6절에서 말한 "yaw 오차가 가장 치명적" 의 그 경우다.

**확인법 (STAGE 3 에서 같이 한다):**
```
RViz: Fixed Frame = base_link, LaserScan 표시
→ 로봇 앞에 물체를 두고, 그 점이 화면에서 +x(앞)에 찍히는지 본다
```
- 앞 물체가 **뒤에 찍히면** → `rpy="0 0 3.14159"` 로 고친다
- 좌우가 뒤집히면 → 라이다 `inverted` 파라미터 / `rpy` 를 같이 본다

## 5. 함정 — TF lookup 타임아웃과 시계

`my_cartographer.lua` 의 `lookup_transform_timeout_sec = 0.2` 때문에
**scan 타임스탬프 시점의 TF 를 0.2초 안에 못 찾으면 그 scan 을 버린다.** 그래서:

- **PC↔젯슨 시계가 어긋나면** TF lookup 이 계속 실패한다
  → README STAGE 0 의 "시계 차 < 1s" 조건이 이것 때문이다
- **기동 순서가 중요하다.** 드라이버·EKF 가 TF 를 내보내기 시작한 **뒤에** Cartographer 를
  붙여야 초기 스캔을 안 버린다. `robot-up.sh` 의 `slam` 모드는 이미 그 대기를 넣어뒀다

> **`/scan` 은 나오는데 지도가 안 생기면 라이다를 의심하기 전에 TF 와 시계를 먼저 본다.**
