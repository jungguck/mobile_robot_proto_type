## 1. PC 는 Jazzy — Humble 안 깔아도 된다

리포 문서(`REMOTE_ACCESS.md` §8, `DEBUG_LOG_2026-09-06.md` §7-C)는 "PC 에 Humble 을 깔아라"
라고 가정했지만, 이 PC(`jk@`, 172.30.1.44)엔 이미 **ROS 2 Jazzy** 가 있다. 젯슨은 Humble 이다.

**cross-distro 가 되는 이유 (오늘 소스 확인):**

| 노드 | 토픽 | 타입 |

## 3. 오늘의 진짜 함정 — conda 가 ROS 파이썬을 가린다

PC 에서 진단 노드를 돌리려니 이게 터졌다.

```
ModuleNotFoundError: No module named 'rclpy._rclpy_pybind11'
The C extension '.../_rclpy_pybind11.cpython-313-...so' isn't present
```

**원인:** 이 PC 의 `.bashrc` 는 conda base(**파이썬 3.13**)를 자동 활성화한다. 그런데 ROS Jazzy
의 rclpy C 확장은 **파이썬 3.12** 용이다. `which python3` 가 `~/miniconda3/bin/python3` 로 잡히면
버전이 어긋나 import 에서 죽는다.

**해결 — ROS 파이썬 노드를 돌리기 전에 conda 를 끈다:**

```bash
conda deactivate                 # 프롬프트에 (base) 남아 있으면 한 번 더
which python3                     # → /usr/bin/python3 여야 정상 (3.12)
```

> `ros_setup` / `jazzy` alias 는 환경만 source 할 뿐 **파이썬 인터프리터까지는 안 고쳐준다.**
> `ros2 run`(C++ 노드)은 영향이 덜하지만, **파이썬 노드/스크립트는 반드시 conda 를 꺼야 한다.**

## 4. 시험 워크플로우 — 명령을 어떻게 보내고, 무엇을 켜고, 어떻게 보나

오늘 정한 원격 시험의 정본이다. 세 갈래를 한 그림으로:

```
   [ 젯슨 robot ] (실제 하드웨어)          [ PC (Jazzy) ] (내 앞)
   노드 전부 기동 (launch, tmux 안)         진단 노드로 구독 + 명령 발행 + 그래프
        │  /odom_raw /odom /ebimu_data /scan 발행    │
        └──────────── DDS (ROS_DOMAIN_ID=0) ─────────┘
```

### 4-1. 젯슨엔 무엇을 시키나 — "노드 다 켜기" (한 방)

메인 launch 하나로 드라이버·IMU·EKF(·라이다)를 전부 띄운다. **tmux 안에서** 띄워야
SSH 가 끊겨도 안 죽는다 (`REMOTE_ACCESS.md` §4).

```bash
# 젯슨 (tmux 안). 오도메트리만 볼 거면 라이다는 꺼서 잡음 줄인다.
ssh robot 'ros2 launch relayrobot_description real_robot_260519.launch.py use_lidar:=false'
```

이 launch 가 띄우는 것: `robot_state_publisher`, `ebimu_publisher`, `real_robot_driver_260519`,
`ekf_filter_node` (+`use_lidar:=true` 면 `sllidar_node`). 노드를 하나씩 분리해 원인 찾을 땐
어제 로그 §8-2 의 단독 기동 명령을 쓴다.

### 4-2. 명령(cmd_vel)은 어떻게 보내나 — PC 에서 발행

명령은 **PC 에서** `/cmd_vel` 로 쏜다. DDS 라 젯슨 드라이버가 그대로 받는다. 두 가지:

```bash
# (A) 키보드 텔레옵 — 실주행/캘리브레이션 주행에 편하다 (PC 에 설치돼 있음)
ros2 run teleop_twist_keyboard teleop_twist_keyboard

# (B) 한 번씩 딱 값만 (스크립트/정밀 테스트용)
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.1}}" --once
```

**비상정지 (항상 다른 창에 준비):**
```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0}, angular: {z: 0.0}}" --once
```
> ⚠️ 로봇이 실제로 움직인다. **바퀴를 띄우거나 주변을 비우고** 할 것.

### 4-3. 데이터는 어떻게 받아 보나 — 구독해서 기다린다

세 층위가 있다. 상황에 맞게 고른다.

| 목적 | 방법 |
|---|---|
| 값 한 번 확인 | `ros2 topic echo /odom_raw --once` (PC 에서 바로) |
| 발행 주기 확인 | `ros2 topic hz /odom` |
| **판단·비교** | **`tools/odom_check.py` (5절) — 이걸 켜놓고 기다렸다 굴리며 본다** |

`odom_check` 가 곧 "구독해서 기다리는 노드"다. 켜두면 2Hz 로 표를 갱신하고, 로봇을 굴리는
순간부터 명령·바퀴·IMU·EKF 값이 채워진다.

### 4-4. 그래프로 확인 — `rqt_plot`

`odom_check` 는 핵심값을 **토픽으로도 발행**하므로 `rqt_plot` 으로 실시간 그래프가 된다.
(PC 에 `rqt_plot` 설치 확인됨. `plotjuggler` 를 원하면 `sudo apt install ros-jazzy-plotjuggler-ros`)

```bash
# 회전 검증: 바퀴 적분 각도 vs IMU 절대 yaw — 두 선이 벌어지면 wheel_base 오차
rqt_plot /odom_check/raw_theta_deg /odom_check/imu_dyaw_deg

# 직진 검증: 명령 경로 vs 바퀴 경로 — 기울기가 다르면 rpm_scale/wheel_radius 오차
rqt_plot /odom_check/cmd_path /odom_check/raw_path
```
원시 토픽도 코드 없이 바로 그릴 수 있다: `rqt_plot /odom_raw/twist/twist/linear/x`.

## 5. 오도메트리 진단 노드 — `tools/odom_check.py`

젯슨이 아니라 **PC 에서** 돈다 (전부 표준 메시지 → cross-distro). 구독:
`/cmd_vel`, `/odom_raw`, `/odom`, `/ebimu_data`. 네 소스를 나란히 비교한다.

**핵심 검증 두 가지 (기구학 상수 검사):**

| 지표 | 계산 | 벗어나면 의심할 상수 |
|---|---|---|
| ① 선속도 스케일 | `odom_raw 경로 / 명령 경로` | `rpm_scale` / `wheel_radius` |
| ② 회전 스케일 | `odom_raw Δθ / IMU Δyaw` | `wheel_base` |

②가 이 설계의 요점이다. **이 IMU 는 자이로(각속도)를 안 주고 절대 yaw 만 준다**
(`/ebimu_data` 가 3필드만 출력, `angular_velocity_covariance[0]=-1`; `ekf.yaml` 주석과 일치).
그래서 yaw-rate 교차검증은 못 하지만, **IMU 절대 yaw 를 회전량의 기준자로 삼으면 줄자 없이도**
바퀴 회전 오차를 잡는다.

**실행:**
```bash
conda deactivate                 # 3절 — 필수
ros_setup
python3 tools/odom_check.py
```

**캘리브레이션 절차:**
- **직진:** 바닥에 1.0 m 표시 → `reset` → 그 지점까지 굴림 → 정지 → ① 값 읽기
- **회전:** `reset` → 제자리 회전 → ② 값 읽기 (줄자 불필요, IMU 기준)
- 누적값 초기화: `ros2 service call /odom_check/reset std_srvs/srv/Trigger`

**발행 토픽 (rqt_plot 용):** `~/lin_scale`, `~/rot_scale`, `~/cmd_path`, `~/raw_path`,
`~/raw_theta_deg`, `~/imu_dyaw_deg`.

**PC 오프라인 검증 완료:** 젯슨 없이 노드가 기동하고, 미수신 토픽은 "(수신 없음)" 으로
표시되며, 6개 토픽이 정상 발행됨을 확인했다.

> ⚠️ 상수(`r=0.0325` / `base=0.22` / `rpm_scale=600`)는 `DEBUG_LOG_2026-09-03` 확정값이다.
> ①②가 어긋나도 **먼저 유령 거리(피드백 stale)를 의심**하라는 게 드라이버 주석의 경고다.
> 상수를 바꿀 땐 재빌드 없이 `--ros-args -p wheel_base:=0.23` 처럼 파라미터로 바로 시험한다.
