# 🤖 Relay Robot Hardware

이 페이지는 프로젝트에 사용된 주요 하드웨어 구성 요소와 사양을 기록합니다.

## DDSM400 모터
- **타입**: Direct Drive Smart Motor (차륜형 로봇용).
- **특징**: 고토크, 정밀 인코더 내장.
- **통신**: Waveshare DDSM 드라이버 HAT 을 통한 JSON over Serial (`/dev/motor`, 115200).

### 통신 규약 (2026-08-22 실측 확정)
| 항목 | 값 |
|------|-----|
| 보드 타입 설정 | `{"T":11002,"type":210}` — 초기화에 포함 (효과는 아래 주석 참고) |
| 속도 제어 | `{"T":10010,"id":N,"cmd":X,"act":10}` |
| 모드 설정 | `{"T":10012,"id":N,"mode":M}` — DDSM210 계열: **0=개루프, 2=속도루프, 3=위치루프** |
| 정지 | `{"T":10010,"id":N,"cmd":0,"act":10}` (= `{"T":10000,"id":N}`) |
| **상태 조회** | `{"T":10032,"id":N}` → `{"T":20011,..,"mil":..,"pos":..,"err":0}` |
| `cmd` / `spd` 단위 | **0.1 RPM** (cmd 100 = 10 RPM). 속도루프 범위 ±2100 |
| 피드백 | `{"T":20010,"id":..,"typ":400,"spd":..,"crt":..,"tep":..,"err":0}` |
| 피드백 시점 | **명령을 받았을 때만** 회신 (주기적 전송 없음) |
| heartbeat | 기본 `-1` = **비활성**. 정지 명령 없으면 무한 회전 |
| **명령 간격** | 여러 모터에 연속 전송 시 **10ms 이상** 띄울 것 (반이중 RS485) |

> ⚠️ **`pos` 는 1회전마다 되감긴다** (0~32767 = 360°). 누적 회전량은 반드시
> **`mil * 32768 + pos`** 로 구한다. 이걸 모르면 "여러 바퀴 돌았는데 제자리" 로 오판한다.

> ⚠️ **명령 사이에 간격을 두지 않으면 버스가 충돌**해서 `{"T":20010,"crc":0}` 이 돌아온다.
> `MotorDriver.drive()` 의 `time.sleep(0.01)` 이 이것 때문이다. 지우지 말 것.

> **`type` 필드에 대하여.** 모터는 스스로를 `typ:400` 이라고 보고하지만,
> 펌웨어(`ddsm_example.ino: set_ddsm_type`)는 `115` / `210` 만 처리하고 그 외 값은
> **조용히 무시**한다 — 이건 소스로 확인된 사실이다.
>
> 다만 **`type:210` 이 구동의 전제조건은 아니다.** 2026-09-16 실측에서 `type:115` 로
> 설정해도 모터가 정상 회전했고, `type` 명령이 성공 시 찍어야 할 `DDSM210` 에코가
> 한 번도 오지 않았다. 실제 보드 펌웨어가 이 저장소 소스와 다를 가능성이 있다.
> **"모터가 안 돌면 type 부터 의심" 하지 말고** `docs/DEBUG_LOG_2026-09-16.md` 8절의
> 순서를 따라라. [[Debugging_Experience#7]]

### 모터 배치 / 부호 규약 (2026-08-22 확정 · 2026-09-16 재확인)
| 항목 | 값 |
|------|-----|
| id = 1 | **오른쪽** 바퀴 |
| id = 2 | **왼쪽** 바퀴 |
| 전진 부호 | R = **음수**, L = **양수** |

> 좌우 허브모터가 거울 대칭으로 장착돼 있다.
> 이 부호는 `MotorDriver` 의 `DIR_R = -1` / `DIR_L = +1` 이 전부 흡수하므로,
> **드라이버 바깥에서는 부호를 건드리지 마라.** ("+ = 로봇 전진") [[Debugging_Experience#9]]

**ID 가 보드에 저장돼 있는지 확인하는 법:** `{"T":10010,"id":3,...}` 을 보내본다.
응답이 **0 바이트**면 그 ID 의 모터가 버스에 없다는 뜻이다. 펌웨어 `ddsm_ctrl()` 은
ID 를 **전혀 검증하지 않고** 그대로 RS485 에 실어 보내므로, 무응답은 펌웨어가 거른 게 아니다.
2026-09-16 에 이 방법으로 `id=1`·`id=2` 가 정상 등록돼 있음을 확인했다.

**좌우 균형 (2026-09-16 실측):** 같은 명령(`cmd 294`, 2초)에 오른쪽 1.010바퀴 /
왼쪽 0.986바퀴. 차이 2.4% — **불균형 없음.**

## RPLidar (2026-09-06 실측 정정)

> ⚠️ 이전에 "A1/A2 계열" 로 적혀 있었으나 **틀렸다.** 실물은 **1,000,000 보드**를 쓰는
> **S2/S3 계열**이다. A1 설정(115200)으로 띄우면 `SL_RESULT_OPERATION_TIMEOUT` 으로 죽는다.

| 항목 | 값 | 근거 |
|------|-----|------|
| 포트 | `/dev/rplidar` (CP2102N, `10c4:ea60`) | udev 규칙 |
| **보드레이트** | **1000000** | 프로토콜 직접 탐색 (115200/256000/460800 전부 무응답) |
| scan_mode | `DenseBoost` | `sllidar_s2_launch.py` |
| model 코드 | `0x81` (펌웨어 1.02 / 하드웨어 18) | `GET_INFO` 응답 |
| 스캔 주기 | **10 Hz** | 실측 `ros2 topic hz /scan` |
| 스캔당 유효 포인트 | **2780개** | 실측 |
| angle_increment | 0.00194 rad (약 0.111°) | 실측 |
| range_min / max | 0.05 m / **40 m** | 실측 (40m 면 S3 가능성) |
| **Topic** | `/scan` | |
| **Frame ID** | `lidar_v1_1` | 메인 launch 가 지정. 단독 launch 기본값은 `laser` 라 다름 |

**단독 실행 시:**
```bash
ros2 launch sllidar_ros2 sllidar_s2_launch.py serial_port:=/dev/rplidar
```
> ★ `serial_port` 를 반드시 넘길 것. launch 기본값이 `/dev/ttyUSB0` 인데 **그건 IMU 다.**
> 메인 launch(`real_robot_260519.launch.py`)는 이미 올바르게 지정돼 있다.

## EB-IMU
- **모델**: E2BOX EBIMU9DOFV5. 포트 `/dev/ttyimu` (CP2102, 115200).
- **역할**: EKF 의 방향(yaw) 소스. 바퀴 오도메트리의 회전 오차를 보정.
- **Topic**: `/ebimu_data` (`sensor_msgs/Imu`)

### 출력 포맷 (2026-08-22 실측)
현재 이 센서는 **자세 3개 필드만** 내보낸다.
```
*ROLL,PITCH,YAW        예: *-5.82,-2.39,135.80
```
9개 필드(`*ROLL,PITCH,YAW,ACCX,ACCY,ACCZ,GYROX,GYROY,GYROZ`) 설정도 가능하지만
지금은 그렇게 설정돼 있지 않다.

> ⚠️ **가속도·자이로 값이 없다.** 따라서 EKF 에서 `v_yaw` 와 선가속도를 쓸 수 없고,
> 절대 yaw 만 사용한다. `ebimu_publisher.py` 는 두 포맷을 모두 처리하며,
> 3필드일 때는 해당 항목의 `covariance[0]` 을 `-1`(미제공)로 표시한다.
> [[Debugging_Experience#11]]

## 전원 (2026-09-06 조사 + 실측)

**현재 구성: 모터와 젯슨은 전원을 따로 공급한다.** (공유 레일이 아니므로 모터 기동 시
전압 강하로 젯슨이 리셋될 위험은 없다. 이 분리를 깨지 말 것 — 아래 '왜 중요한가' 참고)

| 장치 | 입력 전압 | 소비 | 근거 |
|------|-----------|------|------|
| Jetson Orin Nano 개발자킷 | **DC잭 9–20V** (권장 19V) | 유휴 4.74W, 센서 2개 구동 시 4.04W, 모드 **15W** | 캐리어보드 P3768 회로도 `DC JACK POWER PATH ... VOLTAGE:9V-20V` + INA3221 실측 |
| DDSM400 ×2 | 정격 **25.2V** | 정격 0.24±0.07A, 무부하 0.25A, 구속 1.0±0.2A | Waveshare 사양 |
| RPLidar (S2 계열) | 5V | 스캐너 300~350mA, 모터 100mA, 기동 서지 500~600mA | Slamtec 데이터시트 |
| EBIMU | 5V (USB) | 무시 가능 | |

> **2026-09-13 현재 구성 변경 중 — 12V.** 젯슨 DC잭 9–20V 범위 안이라 동작은 정상이나
> 모터는 정격 25.2V 대비 **최고속도가 절반 이하**가 된다(아래 표). 전원 분리는 유지한다.
> 같은 날 **USB 장치 3개가 모두 물리적으로 분리된 상태**가 확인됐다 — `lsusb` 에 허브 2개와
> 블루투스뿐이고 `/dev/motor`·`/dev/rplidar`·`/dev/ttyimu` 가 전부 없다. udev 규칙은 젯슨에
> 남아 있으므로 다시 꽂으면 별칭도 복귀한다. `docs/DEBUG_LOG_2026-09-13.md` 6·7절

### 12V 로 구동할 때 알아둘 것

세 장치 모두 12V 에서 **동작한다 — 2026-09-16 실주행으로 확인됐다.**
(그 전까지 이 항목은 데이터시트 계산에 근거한 추론이었다.)
다만 모터는 정격이 25.2V 라 대가가 있다.

| | 25.2V (정격) | **12V** |
|---|---|---|
| 무부하 회전수 | 400 RPM | **약 190 RPM** |
| 바퀴 선속도 (r=0.0325) | 1.36 m/s | **약 0.65 m/s** |

속도상수가 **15.9 RPM/V** 이므로 최고 회전수가 전압에 정비례한다.
**토크는 안 줄어든다** — 토크상수(0.3 Nm/A)는 전압과 무관하고, 12V 는 속도 천장만 만든다.

> ⚠️ **"로봇이 이상하게 느리다" 는 코드 문제가 아닐 수 있다.**
> 12V 로 물려 있으면 최고속도가 원래 절반 이하다. `rpm_scale` 이나 기구학 상수를
> 다시 의심하지 말 것 — 그 값들은 2026-09-03 에 확정됐다.

### ★ 저속 헌팅 — 순항 속도 하한 (2026-09-16 실측)

**저속에서 속도루프가 심하게 헌팅한다.** 로봇이 뚝뚝 끊기듯 떨리고, SLAM 에 쓰면
IMU 가 튈 정도다. 정상상태(출발 가속 제외) 속도 변동을 재면:

| 속도 | cmd | 변동(표준편차/평균) | spd 범위 |
|---|---|---|---|
| 0.05 m/s | 147 | **28 %** | 62 ~ 227 |
| 0.10 m/s | 294 | 9 % | 241 ~ 343 |
| 0.15 m/s | 441 | 6 % | 391 ~ 481 |
| 0.20 m/s | 588 | **2 %** | 544 ~ 590 |

> ✅ **순항 속도를 0.15 m/s 이상, 가급적 0.20 m/s 로 잡아라.** 12V 최고속도 약 0.65 m/s
> 안이라 여유가 충분하다.
>
> ⚠️ **`act`(가속 파라미터)와 명령 재전송 주기는 원인이 아니다.** `act` 0~100,
> 주기 0.02~0.2s 를 전수 스윕했고 유의미한 차이가 없었다. **다시 시도하지 말 것.**
> (측정은 오른쪽 모터 기준. 왼쪽 확인은 미완 — `docs/DEBUG_LOG_2026-09-16.md` 6절)

### 전원 차단 순서 — 젯슨 먼저, 모터 나중

```bash
ssh robot robot-off        # 모터정지 → 노드종료 → sync → poweroff
# 핑이 끊기고 20초 대기, LED·팬 정지 확인 후 12V 모터 전원 차단
```

- 젯슨은 **SD 카드 부팅**이라 라이브 차단은 카드 손상이다. 반드시 `robot-off` 를 쓴다.
  (`sudo` 는 `poweroff`/`reboot`/`shutdown` 에 한해 NOPASSWD 로 등록돼 있다)
- 모터는 소프트웨어 종료 절차가 **없다.** 12V 를 그냥 끄면 된다.
- **순서가 중요한 이유:** heartbeat 가 비활성이라, 모터가 도는 중에 젯슨을 먼저 끄면
  **정지 명령을 보낼 수단이 사라진 채 로봇이 계속 굴러간다.**
  `robot-off` 1단계가 `/cmd_vel = 0` 을 보내는 게 이것 때문이다.

### 왜 전원 분리가 중요한가

모터 기동·구속 순간 전류가 튀면 레일 전압이 주저앉는다. 젯슨과 레일을 공유하는데
순간적으로 **9V 아래로 떨어지면 젯슨이 브라운아웃으로 리셋된다.**
이 젯슨은 **SD 카드 부팅**이라 쓰기 중 리셋은 곧 카드 손상이다. 실제로 한 번 겪었다.

공유 레일을 쓸 수밖에 없다면: 젯슨 입력단 벌크 커패시터 + 12V 기준 **5A(60W) 이상** 공급.
